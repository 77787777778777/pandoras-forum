# ADR 0011 — The project is Pandora's Forum, and its namespace is `forum.pandoras`

- Status: Accepted
- Date: 2026-11-14
- Supersedes: ADR 0003 decision 1 (keep the first namespace)
- Amends: ADR 0001 D2 (namespace) and M4; user decision U-D4 (the preview origin)
- Records: user decision U-D6

## Context

The project was built under a working name that punned on the name of an existing forum
community. Read uncharitably it was a jab at a person, which was never the point and is not
what the project should be known by. Its NSIDs lived under the owner's personal domain, as
`online.7778777.…`: an authority with a digit segment (ADR 0003 exists because of it), tied to
an unrelated personal handle.

On 2026-11-14 the owner bought `pandoras.forum` and asked for the project to be renamed to
Pandora's Forum, with the collections under that domain (U-D6).

Nothing had been published, which is what makes a clean rename possible:

- every build writes only the `.temp` namespace, which carries no compatibility promise
  (`data-model.md` §1.3);
- no lexicon is published and no DNS `_lexicon` record exists;
- there is no release, no published crate or package, and no deployed indexer;
- `dto/1` does not contain the name.

## Decision

1. **Name.** The product is **Pandora's Forum**. Prose and user interfaces write it that way.
2. **Code name.** Everything a program or a person types is `pandoras-forum`, in the spelling
   its context needs:

   | Where | Form |
   |---|---|
   | command, crates, packages, container image, repository | `pandoras-forum`, `pandoras-forum-core`, `@pandoras-forum/web` |
   | Rust paths, wasm module, metrics | `pandoras_forum_core`, `pandoras_forum_engine.js`, `pandoras_forum_indexer_*` |
   | environment variables | `PANDORAS_FORUM_*` |
   | directories, keyring service, browser storage, Trusted Types policies | `~/.config/pandoras-forum`, `pandoras-forum-md` |
   | HTTP headers and the User-Agent product | `x-pandoras-forum-*`, `pandoras-forum/<version> (+https://pandoras.forum)` |
   | DID document service | `#pandoras_forum_index`, type `PandorasForumIndex` |

   The command is not the shorter `pandora`: other software already installs a program of that
   name (the Syd sandbox's `pandora`, among others), and the owner made the short name
   conditional on its being free.
3. **Namespace.** `NS = forum.pandoras`, whose NSID authority is `pandoras.forum`.
   Development builds write `NS.temp = forum.pandoras.temp`, and the indexer queries are
   `NS.index.*`, as before. The lexicon files are in `lexicons/forum/pandoras/`. At M7 the DNS
   records are `_lexicon.pandoras.forum` and `_lexicon.index.pandoras.forum`.
4. **Hash domain tags.** `fk/1` and `sk/1` hash under `pandoras-forum-fk/1` and
   `pandoras-forum-sk/1` (`data-model.md` §3).
5. **Origins.** The release site (M7) is `https://pandoras.forum`, which is also the publisher
   account's handle and the home of the hosted client metadata. The pre-release preview moves
   from a name under the owner's personal domain to `https://dev.pandoras.forum` (this amends
   U-D4). Test builds therefore never share the release origin or its OAuth client identity.
6. **No compatibility with the previous names.** Records in the previous `.temp` namespace
   are orphaned, as §1.3 always allowed. Local state under the previous directory, keyring and
   browser-storage names is not read or migrated. `xtask migrate-temp` (M7) maps only
   `forum.pandoras.temp` to `forum.pandoras`.
7. **The whole tree is renamed**, archived design documents and earlier ADRs included, so
   that they can still be read against the code. The spike records (ADR 0002 to 0007 and 0009)
   quote requests and answers that were observed under the first names; they were not run
   again, and the opaque values in them (CIDs, revisions) are as observed. Where a record
   depended on the shape of the first namespace, it says so: ADR 0003 (the digit segment it
   tested) and ADR 0001 D2 and M4.

## Consequences

- Every `fk`, every `h16` and every record CID changes, because each hashes an NSID or a tag.
  The key and fold vectors are regenerated by their generators and the reference model
  (`testdata/vectors/README.md`), and the snapshots are re-blessed, in the same change.
- The project's NSIDs are ten bytes shorter, and the authority has no digit segment. No limit
  changes. The questions ADR 0003 answered about a digit segment no longer apply to our NSIDs;
  the Rust NSID validator keeps its digit vectors.
- `threat-model.md` SUP-1 (domain hardening) now applies to `pandoras.forum`, which carries the
  namespace authority, the hosted origin and the publisher handle.
- The Git history, the earlier commit messages and the development branch name keep the
  working name. Rewriting published history was not asked for and is not done here.
- Records that test accounts wrote under the previous `.temp` namespace stay in those
  repositories until their owner deletes them. No client reads them any more.
